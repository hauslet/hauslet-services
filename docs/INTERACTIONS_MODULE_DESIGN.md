# Interactions Module - Technical Design Document

## 🎯 Overview

The **Interactions Module** tracks user behavior on the Hauslet platform to provide immediate analytics value and build a long-term foundation for Machine Learning personalization.

**Key Updates in v2:**

* **Write Buffer:** Uses Redis to buffer high-velocity events, preventing database lockups.
* **Partitioning:** Implements time-based partitioning for the database to manage long-term scale.
* **Bot Filtering:** Adds middleware to flag or drop non-human traffic.
* **Session Merging:** Strategy to attribute anonymous "window shopping" history to users once they sign up.

---

## 📊 Business Use Cases

### **Immediate Benefits:**

* ✅ **Landlord Insights:** "Your listing got 234 views and 5 saves this week."
* ✅ **User Retargeting:** "You viewed these 3 properties; price just dropped on one."
* ✅ **Trending Properties:** Algorithmic ranking for "Hot in [Location]" lists.
* ✅ **Search Optimization:** Promote listings with high Click-Through Rates (CTR).

### **Future ML Capabilities:**

* 🤖 **Collaborative Filtering:** "Users who viewed this also viewed..."
* 🤖 **Personalized Ranking:** Reranking search results based on user's past price/amenity preferences.
* 🤖 **Churn Prediction:** Identifying users likely to stop searching without converting.

## 🗄️ Database Schema (Optimized)

### **1. Interactions Table (Partitioned)**

We use **declarative partitioning** by range (date). This is crucial for performance. It keeps indices small and allows us to instantly "drop" data older than X months if needed without expensive `DELETE` operations.

```sql
CREATE TABLE interactions (
    id UUID, -- Generated by app/worker
    user_id UUID,
    session_id VARCHAR(64) NOT NULL,
    
    interaction_type VARCHAR(32) NOT NULL,
    entity_type VARCHAR(32) NOT NULL,
    entity_id UUID,
    
    context JSONB DEFAULT '{}',
    
    -- Technical & Meta
    device_type VARCHAR(16),
    platform VARCHAR(16),
    is_bot BOOLEAN DEFAULT FALSE,
    
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    
    -- Partition Key
    PRIMARY KEY (created_at, id) 
) PARTITION BY RANGE (created_at);

-- Partitions (Created via migration/worker)
CREATE TABLE interactions_2026_01 PARTITION OF interactions
    FOR VALUES FROM ('2026-01-01') TO ('2026-02-01');

CREATE TABLE interactions_2026_02 PARTITION OF interactions
    FOR VALUES FROM ('2026-02-01') TO ('2026-03-01');

-- Indexes (Applied to partitions automatically)
CREATE INDEX idx_interactions_lookup ON interactions (entity_id, entity_type, created_at);
CREATE INDEX idx_interactions_session ON interactions (session_id, created_at);
CREATE INDEX idx_interactions_user ON interactions (user_id, created_at) WHERE user_id IS NOT NULL;

```

### **2. Interaction Aggregates (Rollups)**

Updated by background jobs. This is what the dashboard reads. It prevents running `COUNT(*)` on millions of rows.

```sql
CREATE TABLE interaction_aggregates (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    entity_type VARCHAR(32) NOT NULL,
    entity_id UUID NOT NULL,
    
    period_type VARCHAR(10) NOT NULL, -- 'hour', 'day'
    period_start TIMESTAMP NOT NULL,
    
    -- Metrics
    views_total BIGINT DEFAULT 0,
    views_unique BIGINT DEFAULT 0,
    saves_total BIGINT DEFAULT 0,
    contacts_total BIGINT DEFAULT 0,
    
    -- Derived Metrics (Calculated during aggregation)
    avg_time_on_page_sec INT DEFAULT 0,
    engagement_score FLOAT DEFAULT 0,
    
    UNIQUE(entity_type, entity_id, period_type, period_start)
);

```

### **3. User Profiles (ML Feature Store)**

Stores the "State" of a user based on their history. Used for recommendations.

```sql
CREATE TABLE user_behavior_profiles (
    user_id UUID PRIMARY KEY,
    
    -- Activity Stats
    last_active_at TIMESTAMP,
    total_sessions INT DEFAULT 0,
    
    -- Preferences (JSONB for ML flexibility)
    preferred_price_range JSONB, -- { "min": 50k, "max": 100k, "weight": 0.8 }
    preferred_locations JSONB,   -- ["Lekki", "Ikoyi"]
    preferred_amenities JSONB,   -- ["pool", "parking"]
    
    -- Scores
    purchase_intent_score FLOAT, -- 0.0 to 1.0
    churn_probability FLOAT,
    
    updated_at TIMESTAMP
);

```

## ⚡ Service Layer & Buffer Strategy

### **1. Write Path (The Buffer)**

```go
// TrackerService pushes to Redis List "interaction_queue"
func (s *TrackerService) Track(ctx context.Context, input Input) error {
    // 1. Bot Detection
    if s.botDetector.IsBot(input.UserAgent) {
        input.IsBot = true
    }

    // 2. Serialize & Push to Redis
    payload, _ := json.Marshal(input)
    
    // Fire and forget (very fast)
    return s.redis.RPush(ctx, "interaction_queue", payload).Err()
}

```

### **2. Batch Worker (The Consumer)**

```go
// Runs in background loop
func (w *BatchWorker) Process() {
    for {
        // 1. Pop 100 items or wait 1 second
        items, err := w.redis.BLPop(ctx, 1*time.Second, "interaction_queue")
        
        if len(items) == 0 { continue }

        // 2. Prepare Batch Insert
        batch := make([]Interaction, len(items))
        // ... unmarshal logic ...
        
        // 3. Bulk Insert into Postgres (Use COPY protocol for max speed)
        err := w.repo.BulkInsert(batch)
        if err != nil {
            // Log error, potentially requeue or write to dead-letter queue
        }
    }
}

```

### **3. Analytics Reader**

```go
// Reads strictly from Aggregate tables for speed
func (s *ReaderService) GetListingStats(listingID uuid.UUID) (*Stats, error) {
    // DO NOT query 'interactions' table here. Too slow.
    return s.repo.GetAggregates(listingID, PeriodDay, Last30Days)
}

```

## 🗓️ Implementation Roadmap

### **Phase 1: Foundation (Weeks 1-2)**

* [ ] Setup Redis instance (or use existing).
* [ ] Implement `interactions` table with partitioning (create Jan/Feb partitions).
* [ ] Build `TrackerService` (API -> Redis) and `BatchWorker` (Redis -> DB).
* [ ] Integrate Client-side tracking (Debounced scroll listeners in React).

### **Phase 2: Aggregation & Dashboards (Weeks 3-4)**

* [ ] Build `AggregatorWorker` (Cron: Hourly). Reads raw data, upserts `interaction_aggregates`.
* [ ] Implement "Listing Analytics" API resolver.
* [ ] **Feature:** "Recently Viewed" list on Homepage.

### **Phase 3: Intelligence (Weeks 5-6)**

* [ ] **Session Merger:** When user logs in/registers, update old `session_id` rows to their `user_id`.
* [ ] **User Profile Builder:** Daily job to analyze history and update `user_behavior_profiles` (Preferred locations/prices).
* [ ] **Marketing Trigger:** Send "Price Drop" email if user viewed listing > 3 times.

### **Phase 4: ML Integration (Future)**

* [ ] Export data to Python/Pandas for model training.
* [ ] Implement `RecommendationService` to serve "Similar Properties".
